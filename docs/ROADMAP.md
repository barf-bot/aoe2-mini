# Roadmap

Ordered by what would make the biggest difference to the game existing as a *game*. Each
item says how we'd know it's done, because "polish" without an exit condition is how
prototypes stall.

## P0 — make it actually playable by someone else

1. **Real-browser smoke test.** No browser here means "playable" is currently proven by a
   stub DOM + a headless render, not by a human clicking. Run the page in
   `browser_navigate`/Playwright, screenshot the live site and compare against
   `preview.png`. *Done when:* a live-site screenshot is attached and matches the sim state.
2. **A\* pathfinding around water.** Movement is straight-line + walkability today, so
   units stall on coastlines and stack against each other. *Done when:* a test paths a
   villager around a water inlet and the route length is within ~15% of optimal.
   **Known limit the 2026-11-04 board-rules pass leaves in place:** terrain and buildings
   went solid (T2), so straight-line movement against a now-solid tile can still
   detour-stall around big blobs — the pass bought solidity, not pathfinding.
3. **Ranged combat + a second unit line (archer).** Shipped 2026-11-11 by the
   OG-content port (`docs/plans/2026-11-11-og-content-port.md`, T4 + T5): `KINDS.archer`
   (hp 30, atk 4, range 4, reload 2, accuracy 80) trains from the Archery Range and
   fights through `Game.projectiles`; the Town Center shoots through the same path, so
   matchups resolve on the vendored stat table instead of the old `CFG.ACQUIRE` guess.

## P1 — content depth

4. **Tech tree / blacksmith upgrades.** Attack/defence/speed upgrades per age; the
   `ageBonus` hook already exists as a multiplier.
5. **More buildings**: lumber camp, mining camp and mill shipped 2026-11-04 (`BLD`,
   hotkeys `L`/`G`/`M`, resource-based drop-off routing); market and watch tower remain —
   the camp pattern (work-radius + drop-off) is now proven by the shipped camps.
6. **Wooden barricade (Feudal Age wall segment) + gated choke points.** 1×1 segment
   placement, needs a `BLD.age` gate so buildings unlock by age; pathing through gaps.
   Folded into phase 2 of the 2026-11-04 board-rules plan.
7. **Win/lose conditions.** Currently there is no game-over; add "destroy the enemy Town
   Center" and a victory overlay.

## P2 — presentation and reach

8. **Sprites instead of discs** — units shipped 2026-11-03 (`assets/sprites.png`,
   regenerated by `tools/gen-atlas.js`); the 2026-11-11 OG-content port
   (`docs/plans/2026-11-11-og-content-port.md`) replaces the drawn cells with ripped
   AoE2 frames for units *and* building footprints. Resource objects and ground tiles
   drawn from `PAL` remain. *Done when:* the same atlas approach covers the resource
   objects without growing the repo past one small PNG.
9. **Save/load** via `localStorage` — `Game` is already a plain object, so `JSON`
   serialisation is nearly free; needs version-stamping.
10. **Sound** — tiny embedded blips for attack/build/age-up.
11. **Touch controls** for phones (tap-select, long-press command), plus a responsive layout.
12. **Replay / seeded challenge** — the `mulberry32` seed is already a shareable handle on a map.

## Phase 2 of the 2026-11-04 rules pass (designed, not yet planned)

Split out of the board-rules request because one plan caps at 8 tasks; phase 1
(`docs/plans/2026-11-04-board-rules.md`) ships the board rules, these ship next.

- **Cancel construction + demolish.** Shipped 2026-11-04 via
  `docs/plans/2026-11-04-cancel-demolish.md`: cancelling refunds 80% of the cost and frees
  the builder; demolishing a finished building refunds nothing (Town Centers exempt).
- **Uniform HUD frame.** Selecting a unit, a building or nothing must render one
  fixed-height overlay instead of today's footer that grows taller for a unit and shifts
  the layout; one place owns the HUD markup. *Done when:* `#info`, `#commands` and
  `#queue` render at identical heights for all three selection states and a check asserts
  the markup shape per state.

## Deferred from the 2026-11-11 OG-content port plan

`docs/plans/2026-11-11-og-content-port.md` ships the part that fits in 8 tasks (vendored
stat tables + `tools/check-stats.mjs`, the §1 generation, the atlas built from ripped
frames, the archer line, ranged combat, win/lose, docs). Left over on purpose:

- **Asset-source swap workflow.** `data/sprites/` + `data/sprites.json` are the single
  documented asset path; refreshing the vendored tables from upstream, or dropping in
  someone's own HD/DE files, still needs a written procedure (fetch, convert, vendor,
  regenerate, with the vendored checksums recorded). *Done when:* `data/README.md`
  documents the steps and re-running them on unchanged input leaves `assets/sprites.png`
  byte-identical.
- **More frames than the ones the plan vendors.** The rip ships 8-direction walk sets,
  `Rot` and `Die` frames per unit; the plan vendors the front-facing idle/walk/work/attack
  a-b cells. *Done when:* a unit's death plays its real `Die` frames and walking picks the
  frame for the movement direction, still inside the one atlas.
- **Farm building art.** The building rip has no farm bitmap, so that cell keeps its
  procedurally drawn frame until real art lands. *Done when:* `data/sprites/buildings/`
  carries a farm frame and the procedural fallback for it is deleted.

## Process items (not features)

- **Split the harness checks by domain.** Today it's 133 checks in one file; group them into
  `economy / build / combat / input / ui` sections so a failure names its area instantly.
- **Pin the toolchain**: a `package.json` with `devDependencies` (`@napi-rs/canvas`) and an
  `npm test` script would make CI possible without touching the game's dependency-free rule.
- **Automate verification on push**: a Pages deploy action that runs
  `node tools/headless-check.js` before publishing, so a red suite can't ship.
- **Decide the repo's home**: currently `barf-bot/aoe2-mini`. Transfer to Barf's own account
  and set up a username Pages site (`dogx.dev`) if this stops being a throwaway.
