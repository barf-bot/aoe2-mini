# Sound (round: P2 #10)

Status: done

## Design

**What you'll see:** the game makes noise. A short thud when one of your units lands a melee
hit, a twang when an arrow leaves, a knock when a building completes, a three-note rise when
you reach the next age, and a victory or defeat chord when the game ends. The header gains a
speaker toggle; muting it survives a reload, and a fresh tab starts unmuted.

**How it works:** sound is synthesised, not shipped — one `playSfx(Game, name)` entry point in
section 5 that builds a short oscillator + gain envelope through the Web Audio API, so the
repo gains no audio files and stays one `index.html` with no build step. The sounds themselves
live in exactly one place, a `SFX` spec table beside the other UI tables: one row per sound
(`hit`, `arrow`, `build`, `age`, `victory`, `defeat`), each with its waveform, frequency sweep,
duration and gain, plus the name of the function that fires it. Call-site checks bind to those
named functions, the same pattern `hudState` uses: the table is the contract, the renderer and
the audio path are its two readers.

`playSfx` bails silently (never throws) when there is no `AudioContext` — which is every
existing check, `render-preview.js` and any browser with audio blocked — when the sound is
muted, or when that same sound already fired inside the current frame, so a 20-unit brawl
makes one thud per frame instead of 20. Mute state is DOM + `localStorage['aoe2mini:muted']`,
read once at boot and written by the toggle; it deliberately does **not** enter `Game`, the
save envelope or `encodeState`, because sound is presentation, not simulation state.

**Not in this round:** background music, a volume slider (on/off only), per-civilisation
voices, real `.wav`/`.ogg` assets, audio for hover and scroll, and any sound the enemy side
makes that the player did not cause (only player-caused events plus the game result sound).

**How we check it:** a harness section that reads `SFX` as the contract — every row complete,
one row per sound, no duplicates; a call-site check per sound proving it fires from exactly
the function the row names (`hitUnit`, `spawnArrow`, the building-complete site, `upgradeAge`,
`setResult`) and from nowhere else; mute persistence (toggle writes the key, boot reads it,
muting suppresses every call); and headless safety (`playSfx` with no `AudioContext` returns
false and the game still runs). `preview.png` must stay byte-identical, and `headless-check`
/ `check-stats` / `audit-line-refs` stay green.

**Hard constraints that survive from `AGENTS.md`:** the game stays one `index.html`; no
framework, no build step, no new image files beyond the one `assets/sprites.png` atlas;
`index.html` is patched, never rewritten; section 4 stays DOM-free; every task names a
proving check and the `Map of this file` banner stays truthful.

Decisions this plan makes where the design left room (fixed here so the executor does not have
to re-decide):

- **`SFX` is a hand-written section-1 table** (`index.html:380-407`, beside `AGES`, `SAVE_PATH`,
  `T`, `PAL`, `TEAM`, `RES_OF_TILE`, `CARRY_COLOR`), not a generated one:
  `tools/check-stats.mjs` renders only `CFG`/`KINDS`/`BLD`/`TECHS`/`SPRITE_SHEET`/`SPRITES`/
  `WORK_ANIM`/`BLD_SPRITES` from `data/`, so `SFX` is authored like `AGES` and `check-stats`
  stays green untouched. `const MUTE_PATH = 'aoe2mini:muted'` goes beside `SAVE_PATH`
  (`index.html:381`).
- **Row shape — five fields, every one REQUIRED:** `{ wave, freq, dur, gain, fire }`. `wave` is
  an `OscillatorType`; `freq` is the frequency list the one oscillator ramps through — two
  entries for a sweep (`hit`/`arrow`/`build`), three for the age/victory/defeat figures;
  `dur` seconds; `gain` the peak; `fire` the firing function's name. One oscillator + one
  gain node per `playSfx` call (the design's own wording), which is also what lets the harness
  tell *which* sound fired by reading the node it built. The authored rows:
  `hit` triangle `[170, 60]` 0.14 s 0.35 · `arrow` sawtooth `[880, 320]` 0.10 s 0.18 ·
  `build` square `[220, 140]` 0.20 s 0.25 · `age` triangle `[392, 523, 659]` 0.60 s 0.30 ·
  `victory` sawtooth `[523, 659, 784]` 0.90 s 0.30 · `defeat` sawtooth `[392, 311, 262]`
  1.10 s 0.28.
- **`fire` names a top-level `function` in the script, exported or not** — `hitUnit`
  (`index.html:869`), `spawnArrow` (`index.html:884`) and `upgradeAge` (`index.html:1696`) are
  exported; the building-complete site (`index.html:1036-1040`) lives inside `updateUnit` and
  `setResult` (`index.html:747`) is §3 — neither is exported. The check resolves `fire`
  against the `^function ([A-Za-z0-9_]+)` names in the script the harness already loads
  (`tools/headless-check.js:28`), so `SFX` cannot name a function that does not exist.
- **`victory` and `defeat` share one call site.** `setResult` (`index.html:747-752`) ends with
  `playSfx(Game, Game.result)` — `Game.result` is exactly `'victory'`/`'defeat'`, i.e. the two
  row names — so one statement covers both rows, and its own `if (Game.result) return` guard
  keeps the game to one chord. Every other row has exactly one call site.
- **The audio handle is `Game.sound = { ctx, at, fired }`** (`createState`,
  `index.html:2747-2757`), the same class of field `Game.view`/`Game.mm`/`Game.sprites` are:
  a non-serialisable presentation handle, absent from `encodeState`'s whitelist
  (`index.html:1877-1906`) and untouched by `resetGame`. Mute itself stays out of `Game` (the
  design): `isMuted(Game)` reads the header button's `aria-pressed` when a state has a `dom`
  and falls back to `storageGet(MUTE_PATH)` when it does not, which is what makes both the
  booted path and the pure fixtures testable. The harness's DOM-only field list
  (`tools/headless-check.js:2641-2652`) and the same list in `docs/GAME_RULES.md:233` gain
  `sound`. `fired` is a plain array — stable object shape per `docs/CONVENTIONS.md:39`.
- **The frame identity is `Game.frame`** (`index.html:2756`, bumped by `startLoop` at
  `index.html:2912`): a name may fire once per value of it, which is the design's
  "one thud per frame" and needs no new state writer.
- **Two mute writers, one setter:** `applyMuteButton(Game, on)` stamps only the button
  (`aria-pressed` + the `Sound on`/`Sound off` label); `setMuted(Game, on)` calls it and writes
  the key. `boot` uses `applyMuteButton(Game, storageGet(MUTE_PATH) === '1')` — "read once at
  boot" with no write, so the `writes=` counts in §13's save/load checks stay untouched — while
  the click handler uses `setMuted(Game, !isMuted(Game))`. The button is addressed by attribute,
  not by class: `stubEl`'s `classList` (`tools/headless-check.js:77`) is a no-op stub, while
  `setAttribute`/`getAttribute` and `textContent` really store values.
- **No sound hotkey this round.** `tools/headless-check.js:2288-2295` pins the banner
  `Controls:` line (`index.html:96`) against the sentence `infoHtml` renders, so a new key
  means rewriting both; the design asked for a header toggle only.
- Six tasks, under the 8 cap — nothing goes to `docs/ROADMAP.md`; T6 marks P2 #10 shipped there
  in the shape of the save/load row (`docs/ROADMAP.md:64-69`) above the still-open items.
