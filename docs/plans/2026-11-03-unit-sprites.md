# Unit sprites (atlas v1)

Status: awaiting go

## Design

**What you'll see:** villagers and militia are drawn as small pixel-art figures in team
colours instead of today's disc and rotated square. A unit flips to face the direction it
walks and bobs 1px while moving. Buildings, trees, ore and ground keep their current
procedural look this round.

**How it works:** `tools/gen-atlas.js` (node + `@napi-rs/canvas`, already used by
`render-preview.js`) draws the frames into one image, `assets/sprites.png`: four 24x24
cells — villager/militia x blue/red — laid out from a frame table that lives in
`index.html` (the tool reads the table the game exports, so art and code cannot drift).
Boot sets `Game.sprites.atlas` once; `drawUnits` uses
`drawImage(atlas, fx, fy, fw, fh, dx, dy, dw, dh)` with a horizontal mirror when walking
left, and falls back to the existing shapes whenever there is no atlas (node, or the
image has not loaded yet). Facing and walk phase become real unit fields (`u.face`,
`u.anim`) so they are testable from section 4. `AGENTS.md` gets a one-line carve-out: the
only image file allowed is `assets/sprites.png`, regenerated by the tool.

**Not in this round:** building sprites, tree/gold/stone/berry sprites, ground tileset,
water animation, 4-direction walk cycles, attack/death animations, the archer. These go
to `docs/ROADMAP.md`; the atlas format already supports adding frames later.

**How we check it:** new checks in `tools/headless-check.js` — the frame table covers
every `KINDS` x `TEAM` pair with in-bounds rects; `setAtlas` stores/clears a source and
the procedural fallback still renders; `u.face` follows movement direction and `u.anim`
only advances while moving. The existing 63 checks keep passing (nothing weakened), the
generator is proven deterministic (two runs, identical sha256), and `preview.png` is
regenerated and visually inspected before the render task is ticked.
